# Список производственных участков и оборудования

Практическая работа по разработке приложения на основе программного интерфейса. Тема — учёт производственных участков и установленного на них оборудования.

## Постановка задачи

Требовалось создать решение из двух частей: серверной и клиентской. Серверная часть предоставляет программный интерфейс для работы с данными, клиентская часть обращается к этому интерфейсу и показывает результат пользователю. Модель данных должна содержать не менее двух связанных сущностей. В каждом из двух разделов интерфейса нужно реализовать получение всех записей, выборку по условию, добавление, изменение и удаление. Данные хранятся в базе SQLite. Интерфейс должен сопровождаться интерактивной документацией.

## Состав решения

Решение включает два проекта.

Первый — серверная часть `ProductCatalogApp.Api`. В ней описаны сущности, контекст базы данных, миграция, объекты передачи данных и два раздела программного интерфейса: производственные участки и оборудование. Для наглядности при первом запуске база заполняется несколькими записями.

Второй — клиентская часть `ProductCatalogApp.Client`. Это веб-приложение, которое не работает с базой напрямую, а получает и изменяет данные через серверную часть. Обращение к серверу вынесено в отдельный класс, поэтому разделы клиента не зависят от подробностей сетевого взаимодействия.

## Модель данных

Используются две сущности.

Производственный участок содержит идентификатор, название и описание. С участком связано установленное на нём оборудование.

Оборудование содержит идентификатор, название, модель, инвентарный номер и ссылку на участок. Каждая единица оборудования относится к одному участку, а участок может содержать несколько единиц. Между сущностями установлена связь «один ко многим».

## Возможности серверной части

Раздел производственных участков позволяет получить список участков, найти участок по части названия, получить участок с перечнем оборудования, добавить, изменить и удалить участок. При удалении участка вместе с ним удаляется связанное оборудование.

Раздел оборудования позволяет получить список единиц оборудования, отфильтровать их по участку, найти по части названия, модели или инвентарного номера, получить одну запись, добавить, изменить и удалить оборудование. При добавлении и изменении проверяется, что указанный участок существует.

Ответы сервера описаны в интерактивной документации, которая открывается по адресу `/swagger`. Там же можно выполнить любой запрос без отдельного клиента.

## Возможности клиентской части

Клиент повторяет возможности серверной части в удобном виде: списки участков и оборудования с поиском и фильтрацией, просмотр подробностей, добавление, изменение и удаление записей. При работе с оборудованием участок выбирается из выпадающего списка, а в списках показывается название участка, а не его числовой идентификатор.

Если серверная часть не запущена, клиент сообщает об ошибке и подсказывает, что нужно сделать.

## Хранение данных

Данные хранятся в базе SQLite. Схема создаётся миграцией при запуске серверной части. Файл базы в репозиторий не добавляется.

## Запуск

Открыть файл решения в Visual Studio, в свойствах решения указать несколько запускаемых проектов — серверный и клиентский — и запустить. Либо воспользоваться файлом `run-all.bat`, который по очереди запускает обе части.

Серверная часть открывается по адресу `http://localhost:5100`, документация — по адресу `http://localhost:5100/swagger`. Клиентская часть — по адресу `http://localhost:5034`. Адрес серверной части для клиента указан в файле настроек клиентского проекта.

## Запуск из командной строки

Потребуется установленный пакет разработчика .NET нужной версии и средство для работы с миграциями Entity Framework Core. Средство устанавливается один раз:

```
dotnet tool install --global dotnet-ef
```

Если оно уже установлено, команду можно пропустить. Проверить установку можно так:

```
dotnet ef --version
```

Дальше все команды выполняются из папки с файлом решения `ProductCatalogApp.slnx`.

Сначала восстанавливаются зависимости:

```
dotnet restore
```

Затем применяется миграция и создаётся файл базы. Серверная часть при запуске также применяет миграцию самостоятельно, но можно сделать это заранее:

```
dotnet ef database update --project ProductCatalogApp.Api
```

После этого серверная часть запускается в одном окне командной строки:

```
dotnet run --project ProductCatalogApp.Api --launch-profile http
```

Серверная часть будет доступна по адресу `http://localhost:5100`, документация — по адресу `http://localhost:5100/swagger`. Это окно нужно оставить открытым.

Клиентская часть запускается во втором окне командной строки:

```
dotnet run --project ProductCatalogApp.Client --launch-profile http
```

Клиентская часть будет доступна по адресу `http://localhost:5034`.

Чтобы не открывать два окна вручную, можно воспользоваться файлом `run-all.bat`, который лежит в папке решения. Он запускает серверную часть, ждёт несколько секунд и запускает клиентскую. Файл рассчитан на запуск в Windows.

Если база данных уже создана и её нужно начать с чистого листа, файл базы удаляется, после чего миграция применяется заново. Имя файла указано в настройках серверной части, по умолчанию это `production.db` в папке проекта серверной части.

Остановить запущенные части можно сочетанием клавиш `Ctrl+C` в соответствующем окне командной строки.

## Использованные средства

Язык C#, платформа ASP.NET Core, работа с базой через Entity Framework Core, база SQLite, документация на основе Swashbuckle, представления Razor, оформление на Bootstrap.
